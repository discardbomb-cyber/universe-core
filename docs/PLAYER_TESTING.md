# Личная проверка Universe Core alpha.5

Текущий JAR — экспериментальная библиотека. В обычной установке у нее **нет игрового интерфейса, карты, клавиши M и доступных команд `/universe`**. Лично сейчас можно проверить установку, загрузку мира, сохранение и подключение к серверу. Игровые возможности подключают будущие адаптеры и аддоны.

Файл: `build/libs/universe-0.1.0-alpha.5.jar`, 191 606 байт. Не устанавливать файл `-sources.jar`.

SHA-256:

```text
D807CD1F1E3D6F04ABB47AB3BE6692428A520A3A9D939BC9CEF829EE55583EBC
```

Для воспроизводимой проверки нужны **Minecraft 1.21.1, NeoForge 21.1.251 и Java 21**. Это проверенная связка; обычному JAR не требуются Sable, Create или Photon.

1. Создай отдельную сборку/профиль Minecraft с NeoForge 21.1.251. В настройках запуска выбери Java 21. Открой папку этого профиля и положи основной JAR в `mods`. Для первого теста используй только Universe Core и NeoForge; оставь одну версию Universe Core.
2. Запусти игру. В списке модов должны появиться **Universe Core**, версия **0.1.0-alpha.5**, ID `universe`. Если мод отсутствует или загрузчик сообщает несовместимую версию, тест установки не пройден.
3. Создай новый творческий мир с включенными командами. Побегай, открой инвентарь, поставь несколько ванильных блоков и сломай один. Мир должен загружаться и работать без падения. `/universe status` в этой обычной установке недоступна — это ожидаемо, команды разработки отключены.
4. Запиши координаты постройки, сохрани мир, полностью закрой игру и открой тот же мир снова. Проверь поставленные и сломанные блоки. Это проверка совместимости с обычным сохранением Minecraft, а не доказательство хранения изменений планеты или корабля.
5. Если нужен серверный тест, установи такой же основной JAR в `mods` отдельного сервера Minecraft 1.21.1/NeoForge 21.1.251 с Java 21. После штатного запуска сервера подключись этим клиентом, поставь блоки, выйди и войди снова. Критерий: сервер запускается, клиент входит, блоки сохраняются, ошибок Universe Core и разрыва соединения нет.

Успешный личный тест означает, что библиотека загружается и совместима с базовой игрой на этой связке. Он не проверяет нагрузку огромных кораблей. Орбита/посадка, production-перенос Sable с пассажирами и стыковкой, посещаемые галактики, Photon-облака и 5000 новых игровых блоков в текущем release отсутствуют. Каталоги и математические API не означают готовую игровую механику.

Чтобы посмотреть **примеры разработки из исходников**, открой PowerShell в корне проекта и запусти:

```powershell
./tools/dev.ps1 runClient
```

Этот запуск автоматически включает `universe.demo=true` и использует ресурсы разработки. В новом мире с командами доступны `/universe status`, `/universe sector milky_way 0 0 0`, `/universe visit space`, `/universe visit barren`, `/universe home` и карта на M. `sector` показывает метаданные; `visit` — тестовая телепортация игрока. Это не полет/посадка корабля. Демонстрационные измерения, экран карты, статичные сферы и GameTest исключены из обычного release JAR.

Native Sable GameTest и реальный клиентский стенд требуют отдельных opt-in профилей разработки и запускаются разработчиком. Фактические результаты и ограничения находятся в `docs/VALIDATION.md`, порядок стендов — в `docs/SABLE_TEST_SETUP.md` и `docs/DYNAMIC_CLIENT_TESTS.md`. Текущий базовый runner прошел 106 JUnit, 19 core GameTest и 10 native GameTest; эти числа не подтверждают готовность всех планируемых игровых возможностей.

При проблеме сохрани `logs/latest.log` из папки именно запущенного профиля, файл из `crash-reports` при падении, версии Minecraft/NeoForge/Java, список установленных модов и короткие шаги воспроизведения. Укажи singleplayer или dedicated server, время ошибки и SHA-256 JAR. При разрыве подключения нужны журналы обеих сторон. При успешном тесте достаточно указать пройденные пункты и использованную связку.
