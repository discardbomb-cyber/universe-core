# Ревью passenger preflight: минимальный standing vanilla mob

Дата: 5 октября 2026. Ревью `docs/SABLE_PASSENGER_TRANSFER_CONTRACT.md` только для одного обычного живого моба, стоящего на одном движущемся native sublevel. **Runtime не запускался, PASS отсутствует.** Игроки с реальным клиентом, seats/passenger trees и docking families остаются обязательными самостоятельными gates. Контракт и source/build не изменены.

## Конкретные замечания для кандидата

**[P1] Разделить живой source entity и сохраненный source ship.** Публичный `@Nullable Entity changeDimension(DimensionTransition)` у generic Entity сначала применяет NeoForge travel hook; при разрешенном межуровневом переходе создает target entity, вызывает `restoreFrom(source)` и `removeAfterChangingDimensions()` у source, затем размещает/регистрирует target. Успешный вызов уже удалил старый объект. Формулировка контракта «source ship не удалять при неполном успехе» верна для корпуса, но не гарантирует живой исходный mob. Кандидат обязан различать эти сущности. Проверки после success должны использовать returned entity, тот же UUID и target registration, а не прежнюю Java reference. Сохраненный корпус не делает перенос моба атомарным.

**[P1] Настоящий standing membership получить до переноса.** Допустимые queries: `Sable.HELPER.getTrackingSubLevel(Entity)` и `getTrackingOrVehicleSubLevel(Entity)` — instance методы ActiveSableCompanion; `getContaining(Level,Vector3dc)` и AABB сами не устанавливают пассажирское владение. Для этой ветки требовать `!mob.isPassenger()`, `mob.getPassengers().isEmpty()`, отсутствие leash/сторонней связи и ровно один выбранный source carrier. Реальный mob должен постоять на deck через обычные native/entity ticks, а не только быть созданным/телепортированным в предполагаемую точку. Затем проверять tracking к source и относительное движение. Прямой `sable$setTrackingSubLevel` как единственная причина успешного membership даст ложное доказательство. Ручной setter, если он позднее нужен для rebind, требует независимого естественного tracking после активации.

**[P1] Не считать dimension-wide pause заморозкой entity.** Пауза physics system останавливает solver sublevels, но не обычные entity ticks. `Mob.setNoAi(true)` выключает AI, а не gravity/collision/delta movement. Поэтому staging в течение нескольких тиков может изменить позицию/health/fire/effects source mob даже при paused ship. В выделенном probe можно выбрать no-AI fixture и ограниченный интервал, но нельзя заявить snapshot одного времени без повторной capture перед `changeDimension`. `setNoGravity(true)` уберет часть физики и сузит тест до размещения, а не standing support. Естественное устойчивое standing после переноса — отдельная необходимая проверка. Все временные fixture flags фиксировать как ограничения теста и сравнивать с исходными.

**[P1] Снимок pose должен соответствовать состоянию моба.** Использовать public `Pose3dc.transformPositionInverse(Vector3dc,Vector3d)` у source и `transformPosition(Vector3dc,Vector3d)` у готового target. Копировать pose/векторы, учитывать rotation point и возможный иной plot storage slot. Сначала подтвердить, что `mob.position()` — мировая позиция в этой Sable ветке; plot position из EntityStickExtension нельзя молча трактовать так же. Для standing identity-frame smoke допускается одинаковый carrier velocity без поворота frames. Положение относительно target, world yaw/pitch и фактический carrier проверять после native/entity ticks. Sable V/ω per-second и vanilla deltaMovement не смешивать численно: frame/carrier velocity policy объявить заранее, а неизвестную разницу не скрывать zero-speed teleport.

**[P1] Состояние проверять шире UUID и имени, без refill.** Public `Entity.restoreFrom(Entity)` вызывает `source.saveWithoutId(new CompoundTag())`, затем штатный `load`, включая virtual additional-save methods. Vanilla source сохраняет UUID, name/tags, Motion, health/effects через subclass, NeoForge persistent data/serializable attachments. Это путь сериализуемого состояния, не гарантия всех transient capabilities/brain references. Минимальный mob fixture должен иметь несколько независимых ненулевых признаков: health ниже максимума, custom name, tags/persistent marker, подходящее whitelist subtype состояние; контролируемый effect можно добавить с учетом тиков duration. Для моба с equipment/inventory сравнивать все occupied и empty slots, не вручную восстанавливать их. Допустимые исключения полного NBT-сравнения задавать заранее: позиция, yaw, объявленная скорость и прошедшие time-dependent ticks. `Entity.load` обнуляет компоненты NBT Motion с |component|>10; последующий changeDimension устанавливает transition.speed, поэтому тест должен проверить выбранный небольшой finite speed напрямую. Произвольные модовые attachments этим не получают приемку.

**[P2] Success и null не заменяют полную проверку границы.** Для выбранного vanilla mob вызвать `canChangeDimensions(sourceLevel,targetLevel)` отдельно: generic `changeDimension` в просмотренном source не вызывает этот predicate сам. Проверить alive/not-removed, целевой loaded безопасный объем, whitelist/type и текущие UUID/revision перед вызовом. `changeDimension` может вернуть null после hook refusal; для standing mob без children refusal в самом первом hook сохраняет source. Но exception может возникнуть позже — после source removal, target registration или post callback. Поэтому catch-all нельзя трактовать как «ничего не произошло». Диагностика обязана перечитать оба уровня по UUID. Не использовать boolean `teleportTo` как доказательство state transfer, особенно для будущего player override.

**[P1] Компенсация — отдельная операция, не rollback.** После успешного переноса новый mob уже живет в target; обратный `changeDimension` создаст еще один объект, может вызвать hooks и отказать. Даже при возврате нельзя гарантировать прежние object identity, ticks, observer events и внешние ссылки. Требовать: preflight отказ — неизменность source/target; success — ровно одна живая UUID binding; failure после side effect — явное состояние partial/needs-recovery с сохраненным source ship и известным текущим местом mob. Не удалять target mob и не создавать клона из сохраненного NBT ради «атомарного отката»: это маскирует потери/дубли. Production journal/recovery остается обязательным будущим этапом.

## Минимальная приемка и остановки

Кандидат standing-mob probe должен показывать последовательные фазы: natural source support → preflight/state capture → готовый staged ship → fresh mob/pose capture → changeDimension result → target UUID/state/registration → обычные entity/native ticks → natural target support и относительное движение → commit source ship. На возврате снимается новый snapshot, используются возвращенные ссылки. Counts фиксировать по UUID во всех relevant уровнях до/сразу после/после settled ticks, исключая test-owned cleanup; source removed и source registration disappearance проверять отдельно.

Необходимый negative smoke: настоящий travel-hook отказ для test UUID/target до vanilla transfer, с точным trigger и сохранением состояния, carrier, source registration и counts; listener снять в finally. Invalid staging проверять раньше entity transfer. По cleanup завершить observer/pause/owned lifecycle и не позволить delayed callbacks оживить сцену. Регрессии хранения корпуса/сундука и V/ω сохранить.

**Остановить расширение/оставить blocker**, если natural tracking не получается, post-step mob перестает стоять на target, требуется неизвестный mixin setter без подтвержденной семантики, source/target UUID дублируется или state mismatch исправляется ручным refill. В таком случае честный результат — placement/teleport probe с ограничениями, а не passenger functionality PASS. Даже успешный реальный vanilla-mob runtime не закрывает подключенного игрока, seats/mixed trees или docking family; их проверки остаются в обязательном плане.

## Уточнение после первого реального passenger run

Evidence: `.tooling/passenger-native-runs/passenger-20261004T222149565/native-gametest.log` — выполнены 13 GameTest, две required ветки roundtrip/compensation остановились на `phase=outward`, `Destination registration/UUID mismatch`; настоящий travel-hook refusal прошел с одним callback и сохраненным source, прежние 10 native тестов прошли. **Полный passenger transfer пока не PASS.** Пройденный hook refusal подтверждает только ранний отказ. Отдельная завершенная TCP development client fixture не является приемкой player-on-ship переноса.

### [P1] Visible-only UUID lookup не равен всем живым сущностям

Повторно прочитан локальный pinned source: `ServerLevel.getEntity(UUID)` вызывает `getEntities().get(UUID)`. `net/minecraft/world/level/entity/LevelEntityGetterAdapter.java#get(UUID)` ищет только в `visibleEntities`; `getAll()` также перечисляет только visible entities. `PersistentEntitySectionManager.java` хранит отдельные `knownUuids` и section storage, а visible storage пополняется при `startTracking`, освобождается при `stopTracking`. При default HIDDEN chunk сущность может быть еще alive/section-owned, но не появляться в visible lookup.

Следствие: immediate `target.getEntity(uuid) == null` не доказывает потерю или отсутствие target entity. Visible-only counts нельзя использовать как полный аудит отсутствия дублей во время hidden phase. Однако returned reference с `!isRemoved()` также не доказывает успешную регистрацию: target add может быть отвергнут. Строгую UUID/state проверку сохранять, но выполнять после явной готовности/settled boundary с контролируемым дедлайном.

### [P1] Join callback фиксирует попытку добавления, не окончательный success

В `PersistentEntitySectionManager.addEntity` NeoForge `EntityJoinLevelEvent` публикуется **до** `addEntityWithoutEvent`; cancellation возвращает false. Проверка duplicate UUID находится внутри последующего добавления. `ServerLevel.addDuringTeleport(Entity)` возвращает void и для обычного Entity вызывает `addEntity`; generic `Entity.changeDimension` не проверяет этот итог и может вернуть target object после source removal даже при отказе join/add. Поэтому event reference полезна для точного владения/cleanup, но событие нельзя считать commit ACK.

На каждом transfer сохранять обе реальные ссылки: старый source и returned entity, а также точно отфильтрованную join reference по UUID/type/target level. Event должен только записывать наблюдение; не создавать/удалять сущности в callback. Если returned и наблюдаемая reference расходятся, или add canceled, состояние остается partial/needs-recovery. Не создавать replacement-клон при null visible lookup и не выбрасывать returned reference из owned cleanup: hidden-but-live target иначе может остаться потерянным для теста.

### Readiness до операции и подтверждение после нее

Точные public APIs в `ServerLevel.java`: `boolean areEntitiesLoaded(long chunkPos)` и `boolean isPositionEntityTicking(BlockPos pos)`. Первое проверяет статус загрузки entity data, второе — position section ticking плюс entity-ticking range DistanceManager; они решают разные части readiness. Полный блоковый chunk или наличие native ship сам по себе не заменяет обе проверки. Требовать bounded ожидание **до changeDimension** на фактическом target world position и соответствующем ChunkPos.asLong, а также поддерживать target загрузку на время post-check. Не применять проверки к source storage-grid координатам вместо target world позиции standing mob.

После вызова не ослаблять criteria: UUID/type/state returned объекта, reference identity join/return, source removal, target world level и позиция, затем при readiness `target.getEntity(uuid) == returned`, естественный tracking/support после обычных native/entity ticks. Если дедлайн истек, оставить отчет с фазой и полными known-owned references; это FAIL, не разрешение проигнорировать registration. Сравнение counts становится содержательным при одинаковой объявленной видимости/готовности наблюдаемых source/target позиций. Internal `knownUuids`/section storage не открывать reflection или protected доступа ради обхода public API.

Компенсация по-прежнему является новой изменяющей операцией: source entity могла быть удалена до обнаружения hidden/add failure; source ship может быть сохранен, но atomic rollback не доказан. Root/агенты исправляют readiness и reference ownership; эти исправления не проверялись данным ревью runtime. Текущий контракт/source/build, Java/Gradle и игровые процессы не затронуты.

Временный scoped non-cancelling join observer сохраняет точную owned reference для cleanup, фильтруя type/UUID/owner/level и снимаясь в finally. Исторический run `passenger-20261004T222149565` остается failed и не переименовывается в успешный.
