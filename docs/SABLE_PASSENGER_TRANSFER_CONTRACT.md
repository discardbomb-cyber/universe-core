# Контракт исследования passenger/docking transfer — Sable 2.0.5

Дата: 5 октября 2026. Этот файл фиксирует первоначальное read-only исследование API; автор исследования не изменял код и не запускал Java/Gradle. Последующий отдельный stationary Villager milestone реализован и фактически проверен оркестратором: [13 native required и границы доказанного](SABLE_PASSENGER_PROBE_IMPLEMENTATION.md). Production passenger/docking functionality PASS по-прежнему отсутствует.

## Evidence и воспроизводимость

Pinned Sable JAR `sable-neoforge-1.21.1-2.0.5.jar`, SHA-256 `c8710f85bc780bbf523e6726ceaaf76dd0b8c61479db497b382c6bb34317e7ab`; Companion 1.6.0. Public access flags, JVM descriptors и generic signatures прочитаны непосредственно из classfiles PowerShell-скриптом `.tooling/proposals/passenger-transfer/InspectPublicSable.ps1`. Скрипт не исполняет Java и не переносит реализации serializer. Статика методов отмечена по ACC_STATIC. Дескрипторы подтверждают наличие API, не поведение mixins/native engine.

Minecraft/NeoForge source прочитан из локального `.tooling/gradle/caches/neoformruntime/intermediate_results/sourcesAndCompiledWithNeoForge_*_output.jar` для 1.21.1/21.1.251: `net/minecraft/world/entity/Entity.java`, `net/minecraft/server/level/ServerPlayer.java`, `net/minecraft/world/level/portal/DimensionTransition.java`. Ниже порядок vanilla операций — по этим исходникам, а не по документации более нового Minecraft. Sable source соответствует commit `6966d2928340de7631abcecf8549904b877df0a8`; web-fetch конкретных файлов вернул cache miss, сетевой read из shell также недоступен. Поэтому семантика Sable tracking/freeze здесь явно не выдается за подтвержденный source/runtime результат.

Mixin interfaces имеют public методы, но расположены вне `api/`: наличие не гарантирует стабильного transfer-контракта. Freeze не объявлять per-body physics pause, сохранением экипажа или гарантированным ожиданием клиента. Прежде чем использовать, отдельно проверить `mixin/player_freezing/{PlayerMixin,ServerPlayerMixin,LocalPlayerMixin,PlayerListMixin}.java`: условия таймаута, UUID lookup, dimension change и обмен с реальным клиентом. Не вызывать raw setters и push/pop как замену server teleport; matching push/pop должен быть локальным try/finally, без асинхронной смены уровня внутри временно измененных координат.

Companion `dev/ryanhcode/sable/companion/math/Pose3dc` предоставляет `Vector3d transformPosition(Vector3dc,Vector3d)`, `transformPositionInverse(Vector3dc,Vector3d)`, `transformNormal(Vector3dc,Vector3d)`, `transformNormalInverse(Vector3dc,Vector3d)` и overload для Minecraft Vec3. Для capture позиции применять полный pose inverse, включающий rotation point; не вычитать только origin. Tracking, plot position и Minecraft world position сначала сопоставить на реально движущемся корпусе. Sable V/ω измерены в simulation seconds; Entity deltaMovement нельзя переносить теми же численными значениями без отдельной проверки единиц и carrier velocity.

## Vanilla transfer: подтвержденный порядок и ловушки

Публичный путь с результатом: `@Nullable Entity Entity.changeDimension(DimensionTransition)` и override `ServerPlayer.changeDimension(DimensionTransition)`. `DimensionTransition` имеет constructor `(ServerLevel, Vec3 pos, Vec3 speed, float yRot, float xRot, PostDimensionTransition)`, а также canonical constructor с `boolean missingRespawnBlock`; `DO_NOTHING` и `PLACE_PORTAL_TICKET` доступны. Calling public API допустим; копировать `restoreFrom` или upstream protected serializers в Universe не требуется.

У обычного Entity: NeoForge travel hook может отказать → snapshot непосредственных passengers → `unRide()` → рекурсивный `changeDimension` каждого passenger → создание нового entity в другом уровне → public `restoreFrom(Entity)` → удаление source через штатный lifecycle → установка позиции/скорости → добавление в target → `startRiding(newParent,true)` для успешных пассажиров → post callback. Возвращенная ссылка может отличаться от source; UUID/ссылки проверять по результату, не продолжать работать со старым Java object. **Это не атомарное family transfer:** null у части детей не приводит к автоматическому rollback уже перенесенных. У generic Entity source применяет старый `getXRot()` при moveTo, а не переданный xRot: итоговый pitch проверять отдельно.

У ServerPlayer: travel hook/null gate → при межуровневом переходе ClientboundRespawn/difficulty/permissions → removePlayerImmediately → revive/setServerLevel → connection teleport/resetPosition → addDuringTeleport → level/player info/effects → post callback → attachment resync и changed-dimension event. Переносится живой объект/connection, не NBT-клон игрока. В этом override не обнаружена установка `DimensionTransition.speed()` и generic recursion passenger tree. Поэтому явное восстановление/проверка player deltaMovement и дерева обязательны; нельзя считать поведение базового Entity унаследованным.

Также public `void ServerPlayer.teleportTo(ServerLevel,double,double,double,float,float)` делает camera reset и `stopRiding`, затем вызывает changeDimension с ZERO speed/DO_NOTHING; возврат void не подтверждает успех travel hook. Overload `boolean teleportTo(ServerLevel,double,double,double,Set<RelativeMovement>,float,float)` добавляет POST_TELEPORT ticket, снимает riding/sleeping, но возвращает true после вызова void-ветки: для cross-level отказа это не достаточный success signal. Предпочтительный кандидат — changeDimension с проверкой returned entity/current level/registration. Нельзя вручную подменять respawn packets вместо штатного player API.

Entity public `getPassengers()`, `getSelfAndPassengers()`, `getRootVehicle()`, `getVehicle()`, `startRiding(Entity,boolean)`, `stopRiding()`, `unRide()`, `getDeltaMovement()`, `setDeltaMovement(Vec3)` позволяют capture/remount. `startRiding` возвращает boolean и проверяет вместимость/циклы/NeoForge mount hook; force=true не означает безусловный успех. Для player startRiding дополнительно обновляет положение через connection. Membership на палубе не равен vanilla riding edge; один AABB может включать соседние корабли/посторонних.

## Docking family: граница доказанного API

`api/physics/PhysicsPipeline.java`: public `<T extends PhysicsConstraintHandle> T addConstraint(PhysicsPipelineBody,PhysicsPipelineBody,PhysicsConstraintConfiguration<T>)`. `FixedConstraintConfiguration(Vector3dc pos1,Vector3dc pos2,Quaterniondc orientation)` и `void validate(ServerSubLevelContainer,PhysicsPipelineBody,PhysicsPipelineBody)` доступны. `PhysicsConstraintHandle` содержит `remove()`, `isValid()`, `setContactsEnabled(boolean)`, `getJointImpulses(Vector3d,Vector3d)`, `setMotor(ConstraintJointAxis,double,double,double,boolean,double)`.

Public enumeration/export всех scene constraints в исследованном интерфейсе не найден. `SubLevelHelper` constant pool ссылается на `BlockEntitySubLevelActor.sable$getConnectionDependencies()`; actor method возвращает `Iterable<SubLevel>`. Поэтому getConnectedChain нельзя объявлять исчерпывающим экспортом произвольных Rapier joints. Universe `DockingController` сейчас является логическим контроллером, а не доказательством native сварки. Разрешать сначала только собственные зарегистрированные docking edges с known configuration/handle ownership; любые внешние joints/contraptions или несогласие dependency graph — отказ до переноса. Для family потребуется staging всех членов, UUID binding map и восстановление известных edges после регистрации всех target bodies. Handle нельзя перенести между pipelines; без source/runtime проверки базиса joint anchors пересоздание fixed joint остается исследовательской задачей.

## Порядок предлагаемой реализации и приемка

1. Server-side зафиксировать bounded family/revisions (начально 2 корпуса), graph passenger roots и UUID (начально до 8 entities, глубина до 4); исключить смерть/disconnect/sleeping, leashes, неизвестные seats/контроллеры и outside joints. Определить carrier через tracking/vehicle плюс зарегистрированное seat/boarding ownership; AABB использовать только как кандидатов. Сохранить source reference и полный allowed entity state через штатные публичные API; живого player не сериализовать ради клонирования.
2. Подготовить и проверить все target корпуса/velocities/known joints до удаления source. Рассчитать target standing/seat positions полным pose transform, collision volume и remount order. Применимая pause/quarantine должна быть доказана отдельно: dimension-wide pause только в однотестовом мире. Перепроверить permissions и неизменность экипажа перед первым side effect.
3. Для standing whitelist entity проверить перенос по returned object и регистрации. Для riding tree выбрать **одну** стратегию: штатная root recursion либо явный detach/move/remount; не переносить ребенка дважды. Для mixed tree с ServerPlayer отдельно проверять override и реальные mount results. Обработать hook refusal/partial success и disconnect; source ship не удалять при неполном успехе. Перемещение обратно — compensating operation, также может отказать; неизбежно нужен journal/recovery, а не обещание atomic rollback.
4. Подтвердить live player server location и **реальный client**: respawn/teleport подтвержден, target ship tracked/rendered, нет kick/rubberband, корректные standing/seat movement, inventory/effects/health/UUID, late packets не восстанавливают old tracking. PostDimensionTransition callback и наличие объекта на сервере не являются client readiness ACK. Synthetic ServerPlayer/FakePlayer может проверить только серверную ветвь; не засчитывать как клиентскую приемку.
5. Отдельные проверки: обычный standing passenger; seat tree с мобом; подключенный живой player пешком/сидя; roundtrip с ненулевыми V/ω; две native fixed-linked поверхности с сохранением relative pose/движения; отказ hook у одного участника; invalid target handle; disconnect в transfer; external constraint; повтор command; cleanup/restart. Для каждого — exact before/after entity counts и UUID bindings, нет дублей/потерь/инвентарного refill, исходный graph сохраняется при preflight отказе. Native GameTest и реальный клиентский multiplayer отчет обязательны и не заменяют друг друга.

**Открытые blockers:** public per-body staging quarantine не доказана; freeze/tracking semantics и packet timing не проверены; неизвестные scene joints нельзя исчерпывающе экспортировать найденным API; mixed passenger tree перенос не атомарен. До закрытия этих условий функциональность passenger/docking transfer не объявляется реализованной или PASS. Source serializers и protected internals не копировались; runtime-кандидат не добавлен.
