## Boundary и восстановление

[SubLevelPhysicsSystem source](https://github.com/ryanhcode/sable/blob/6966d2928340de7631abcecf8549904b877df0a8/common/src/main/java/dev/ryanhcode/sable/sublevel/system/SubLevelPhysicsSystem.java) показывает последовательность: `prePhysicsTickBegin` → обновление mass data → body `prePhysicsTick` → публичное pre-event → queued forces → `pipeline.physicsTick(dt)` → removals → update poses → post-event. Следовательно pre-event не является последней операцией перед solver: queued forces еще могут изменить результат. Фильтровать событие по конкретному physics system/измерению и одноразовому состоянию сеанса. Не выделять/удалять sublevels внутри обхода physics callbacks без отдельного доказательства безопасности.

После A: на выбранной границе получить source V/ω и сохранить копии; для identity frame целевые значения равны снимку. У destination прочитать текущие Vd/ωd и однократно вызвать `addLinearAndAngularVelocity(V−Vd, ω−ωd)`. Сразу повторно прочитать значения; затем проверить поведение на следующем post-event. Не прибавлять снимок к уже движущемуся destination. Это последовательная операция, не атомарный setter. Исключение или нечисловой readback запрещает commit источника.

`dt` брать из события: в проверенном source `1/20/substeps`, секунды; принимать только конечное положительное значение. Для восстановления velocity **нет умножения на dt**. dt используется при оценке траектории/сил и в журнале. Записывать все реально пройденные source/target подшаги, не считать задержку `runAfterDelay(1)` одним физическим шагом и не компенсировать неизвестный elapsed time выдуманным ускорением. Пока native convention не подтверждена, не применять перенос между повернутыми или движущимися frames.

## Staging: предел безопасной изоляции

В исследованных публичных `RigidBodyHandle`, `PhysicsPipeline`, `PhysicsPipelineBody`, `ServerSubLevel` не найден per-body `disableSimulation`, `setKinematic`, `sleep` или collision-disable для обычного корабля. API `KinematicContraption` относится к другому объекту и не переключает существующий ServerSubLevel. Pipeline `remove/add` — изменение native lifecycle, а не гарантированный staging freeze; не применять как замену карантину.

`setPaused(true)` выключает stepping **всей** системы измерения; pipeline tick, tickets и некоторые actors продолжают работать. В выделенном одноразовом тестовом мире это допустимый контроль с восстановлением исходного paused-флага в cleanup. В общем сервере это затрагивает чужие корабли и не является production-изоляцией. Без отдельного карантинного механизма staging может падать, сталкиваться и воздействовать на мир до commit; нельзя обещать безопасный concurrent transfer. Существующий probe ждет handle через game ticks и проверяет блоки/сундук: он не обеспечивает такой карантин.

## Минимальный native тест после A

1. Сохранить действующие control tests roundtrip/occupied/unsupported без изменения критериев. Создать асимметричный поддерживаемый корпус, без пассажиров/constraints, identity orientation и статические frames с одинаковым масштабом. Ненулевые V и ω задавать раздельно и совместно; ожидаемые компоненты/допуски взять из фактической A, не расширять допуски ради зеленого теста.
2. В отдельном изолированном мире получить baseline destination без restore и source без transfer при тех же fields, substeps и расписании. Нулевой контроль должен оставаться отдельным: перенос нулей не подтверждает ненулевую скорость. Записать размер массы, poses, runtime IDs, pre/post V/ω, dt и количество подшагов. Проверить getters/setters сначала на одном body.
3. Подготовить destination с сохранением source. В согласованной одноразовой pre-фазе выполнить delta restore, immediate readback и post-step сравнение с контрольной ветвью. Сравнивать сохраненный snapshot на его границе; если source продолжал движение при staging, не выдавать snapshot за актуальное состояние source на момент commit. Для roundtrip повторить новую capture, не использовать старую скорость первого перехода.
4. Негативная ветвь invalid handle: до destination allocation обнаружить null/removed handle или передать отдельно удаленный owned fixture в проверку readiness. Не удалять настоящий source ради получения invalid handle. Ожидать конкретный отказ, неизменные source UUID, registration, blocks, chest inventory, logical identity и число destination objects. Source velocity сравнивать на той же paused границе либо с no-transfer control; естественное движение не считать повреждением. Проверка invalid fixture должна быть связана с проверяемым guard, а не искусственной несвязанной ошибкой.
5. После verified restore допускается удаление source; failed restore удаляет только owned staging, source сохраняется. Cleanup одноразового теста не является доказательством production rollback. Восстановить paused-флаги и удалить hooks независимо от результата.

Успех IDEA-006 требует actual runner с required tests, ненулевыми V/ω, immediate и post-step assertions, отдельной negative branch и сохраненными прежними controls. A подтверждена указанным root run; IDEA-006 еще не проверена; бесшовность, безопасный live staging и cross-frame перенос этот контракт не подтверждает. Дополнительные DTO не создавались.

## Кандидат после подтвержденной A

A измерила: impulse local J/m, additive V/ω world; две substeps, dt=0.025 s. Native position float32: тестовая сцена остается около X=128..256, Y=240, Z=−64, а не тысяч блоков. Единицы additive API принимаются из фактической калибровки, не из имен методов.

Добавлены две required функции в существующий класс: `nonzeroVelocityRoundTrip`, `unavailableVelocityPreservesSource`, отдельный batch на каждую. Прежние три функции и их критерии сохранены. Capture/restore выполняются на GameTest scheduled phase с обеими системами paused, без world allocation/deletion из physics callback. Paused pipeline все равно вызывает `pipeline.tick()` (Rapier очищает accelerator cache), контейнер allocation синхронно вызывает `onSubLevelAdded → pipeline.add`; collider/mass setup дополнительно прогревается обычными тиками destination. Затем destination снова paused, source getters проверены на неизменность и destination pose возвращается к source orientation. Проверяется mass equality. Входные V=(2,.4,−.7), ω=(.15,.25,−.1); delta restore использует два native getter, immediate readback и wakeUp. У source capture boundary остается фиксированной, пока destination прогревается.

Source служит настоящей no-transfer control branch: он сохраняется registered и получает одновременно с destination 0.1 s обычных native substeps. Gravity и universal drag должны совпадать в обоих измерениях; substeps должны быть calibrated 2. Это gate стенда, а не предположение о произвольных измерениях. Скорость после действия gravity/drag сравнивается с source, а не с неизменным старым V. Также сравниваются displacement/0.1 s и quaternion delta; линейная скорость, ω и изменения pose обязаны быть measurably nonzero. Допуски заранее ABS=.01 + REL=.05·|expected|, относительная angular pose ошибка <.01 rad; минимум углового движения .005 rad. Пауза после fourth post-event разрешена только этому однотестовому batch; при обоих завершенных интервалах validation/removal откладываются на scheduled GameTest phase. Source удаляется после contents/identity/registration/immediate-readback/activation подтверждений. Для return leg снимается новый snapshot уже двигавшегося destination, а не старое значение первой capture. Identity относится к frames; фактическая orientation тела может измениться после активации.

Негативная branch проверяет тот же `stageVelocity → captureHandle` до allocation. Resolver зависимости намеренно возвращает реальный removed handle отдельного owned fixture; guard отвергает `!isValid()` с точной причиной `Native velocity capability unavailable`. Настоящий source не удаляется и остается с исходными native V/ω, UUID, marker, четырьмя states, chest contents; source/target/owned counts неизменны относительно начала операции. Это fault injection **недоступной capability**, не доказательство естественного отказа JNI getter у живого тела. Fake exception не используется. Для nullable resolver тот же guard предусмотрен, отдельный required test для null пока отсутствует.

Cleanup unregisters observer, drains owned removals вне callback и восстанавливает исходные paused flags в finally. Кандидат включает 120-tick watchdog до GameTest timeout, чтобы ошибочное отсутствие callbacks не оставляло системы paused. Между callback и scheduled cleanup нет произвольного live server API. Никакой production quarantine этим не реализуется.

**История согласованности предыдущего среза (до диагностического исправления):** первые изменения уже были применены в `src/sableTest/.../SableNativeTransferTests.java` до получения сообщения root о заморозке source. После сообщения source не менялся. Proposal содержит дополнительно watchdog, проверку mass equality и исправленный комментарий; он пока не скопирован обратно. Root должен сверить число обнаруженных тестов текущего runner и применить proposal только после окончания своего прогона. Gradle/Java сборка и тестовый runner здесь не запускались; отчет IDEA-006 о PASS отсутствует.

## Диагностика обратного load после первого native run

Root runner `.tooling/test-runs/20261004T183858438Z-24432/sable-gametest.log` обнаружил 8 required tests: семь прошли, velocity roundtrip упал с `Diamond inventory mismatch` после подтвержденного leg=0. Это **не PASS IDEA-006**. Исправленный proposal применен в source по разрешению root; Java/Gradle здесь не запускались.

Отличие от старого проходящего roundtrip: velocity branch выполняла removal и повторную allocation того же storage slot в одной scheduled task. Возвращен существующий `waitForRemoval` с переходом в следующую обычную GameTest-фазу. По локальному байткоду `.tooling/sable-plot-javap.txt`, `ServerLevelPlot.onRemoveChunkHolder` удаляет holder из `updatingChunkMap`, отмечает map modified и вызывает `setLoaded(false)`/`ServerLevel.unload`. Нулевой registration count сам по себе не доказывает отсутствие старого chunk/BE в vanilla lookup cache. Связь потери inventory со stale lookup — гипотеза до следующего root run; задержка не объявлена production synchronization barrier.

Добавлены `SABLE_VELOCITY_BE`/`SABLE_VELOCITY_BE_LOOKUP`: phase/leg, dimension, UUID, source/target/owned counts, identityHashCode chunk/BE, removed/registered flags, direct plot BE, level lookup BE и совпадение объектов, число loaded/pending positions, serialized BE count и полный chest NBT. Точки: source validation, after native save, destination before load, after load до level lookup, after lookup, after warmup, after activation до commit, survivor сразу после commit и после lifecycle wait. Ошибки inventory теперь включают phase/dimension/UUID/pos и фактические stack counts.

Перед allocation native `snapshot.chunks[*].block_entities` обязан содержать ровно один chest и совпадать с `chest.saveWithFullMetadata(registryAccess)` целиком; исключается только chunk-envelope `keepPacked`. После load целиком сравнивается full metadata destination с source. Публичный полноценный serializer существует: локальный pinned bytecode использует `LevelChunk.getBlockEntityNbtForSaving`, который вызывает `BlockEntity.saveWithFullMetadata`; load применяет `BlockEntity.loadStatic`/`LevelChunk.setBlockEntity` либо packed NBT. [Закрепленный ServerLevelPlot source](https://github.com/ryanhcode/sable/blob/6966d2928340de7631abcecf8549904b877df0a8/common/src/main/java/dev/ryanhcode/sable/sublevel/plot/ServerLevelPlot.java). Ручной ремонт `Items`, двух stack или замена пустого NBT не добавлены. Если full save/load или warmup снова меняет inventory, кандидат должен остаться FAIL с конкретной phase, а source нельзя коммитить для этого leg.


## Фактическая узкая приемка и последующий failure-path patch

Подтвержден root run `.tooling/alpha4-native-transfer-compensation.log`: **All 10 required tests passed**. Успешны 3 прежних transfer controls, обе velocity branches и калибровки A/B. На обоих velocity legs full chest NBT, 7 diamonds/19 iron ingots, остальные пустые слоты, marker и block states сохранены без refill. Leg 0: capture V=(2,.4,−.7), ω=(.15,.25,−.1), post V≈(1.98210,−.69742,−.69374), ω≈(.14963,.24677,−.10047), dt=.1 s. Leg 1 использует новую capture этих post-values, затем post V≈(1.96437,−1.78500,−.68753), ω≈(.14908,.24362,−.10091). Это приемка узкого native test-only roundtrip identity frames при одинаковых gravity/drag, двух substeps и whitelist корпуса; не production staging, пассажиры, constraints, crash recovery или произвольные BE.

После этого успешного прогона исправлены два reviewer defects в transfer-файле: `guarded` сразу возвращает после `stopped`; cleanup независимо пытается освободить ticket и удалить каждое owned тело, собирает exceptions через suppressed, затем независимо drains все задействованные уровни и restores hooks/paused flags в finally. Владение удаляется только после подтвержденных ticket release и отсутствия регистрации этого объекта. Ошибка любого этапа оставляет неочищенный объект в owned для явного повторного cleanup; успешный ticket release запоминается, чтобы retry не повторял уже выполненный этап.

В existing required unavailable-capability test добавлена реальная scheduled regression: после cleanup отложенный guarded callback пытается создать непустой native stone body, force-load ticket и зарегистрировать observer. Следующая GameTest-фаза проверяет неизменные counts обоих контейнеров, отсутствие source UUID и утечек owned/listener. Непустой корпус предотвращает ложный зеленый результат из-за автоматического удаления пустого sublevel. Сохранность инвентаря проверяется до cleanup теми же строгими criteria. Количество required tests не изменено. Новая версия failure-path patch **еще требует повторного root native run**; Java/Gradle здесь не запускались.


## Финальная подтвержденная версия

Финальный root runner: `.tooling/alpha4-native-final.log`, **All 10 required tests passed**, exit **0**, 10 GameTest за **3.538 s**. Этот прогон включает failure-path patch: stopped guard, независимые cleanup попытки и реальную scheduled regression после cleanup. Независимый `ideas_review` не обнаружил дефектов cleanup и подтвердил, что regression проверяет попытку мутации настоящей native сцены после остановки, а не только значение переменной. Ранее отмеченная необходимость повторного root run выполнена; предыдущие статусы FAIL/unverified выше относятся к историческим версиям кандидата.

Подтвержден только выделенный GameTest-профиль pinned Sable 2.0.5: whitelist четырех блоков/vanilla chest, полные NBT и logical marker на обоих legs без refill, новые capture на return, world additive V/ω в identity frames, immediate readback, фактические native substeps и retained-source control при одинаковых gravity/drag. Также подтверждены отказ недоступной capability с сохранением source и подавление delayed callback после cleanup. 3.538 s — длительность маленького набора тестов, не норматив production-переноса.

Dimension-wide pause остается исключительно тестовой изоляцией. Финальный PASS не доказывает per-body staging freeze, перенос между различными/движущимися frames или полями gravity, пассажиров, constraint families, произвольные BE/capabilities, unloaded plots, большие корпуса, клиентскую multiplayer-синхронизацию или crash recovery. Независимые cleanup попытки и сохраненное владение обеспечивают возможность retry, но не являются доказательством восстановления после процесса/аварии. Java/Gradle здесь не запускались; исходники после финального root run не менялись. IDEAS, PLAN и VALIDATION находятся под управлением root.
