# Стенд чистой корабельной модели

Запуск: 4 октября 2026 года, Java 21.0.12.1 (Temurin), Windows 11 amd64. Проверка завершилась `PASS`. Gradle и Minecraft не запускались.

Повторение из корня проекта: `& ./tools/ship-model-benchmark.ps1`. Для другого расположения Java 21 передать `-JdkPath`. Скрипт компилирует только `ships/*.java` и собственный проверочный класс через `javac` в уникальный временный каталог. Проверяет версию компилятора и использует `-source 21 -target 21`: в текущей песочнице `--release 21` выдавал ошибку закрытия ресурсов после записи class-файлов. Временные файлы оставлены для инспекции; конфигурация сборки не меняется.

## Сценарий

Одноблочная оболочка размером 1024 × 256 × 256, с X от −512 до 511. Условное число занятых блоков вычисляется как объем внешнего параллелепипеда минус объем внутреннего: **1 173 512**. Блоки не создаются: стенд вычисляет число занятых ячеек каждой граничной секции аналитически. Из 16 384 возможных секций сохраняются **4 232**; 12 152 внутренних пустых секций вообще не представлены. Масса условного блока равна 0,5.

| Проверка | Результат отдельного запуска |
| --- | --- |
| Первичное создание сводок | 4 232 обращения к секциям, 4 232 обновления агрегатов |
| 100 000 аналитических поз орбиты после 20 000 прогревочных вычислений | 0 обращений к сводкам, 0 обновлений агрегатов, 0 копирований снимка |
| Изменение 32 секций с повтором каждого события | 64 обращения, 32 обновления агрегатов, 0 копирований снимка |
| Итог после удаления одного условного блока из каждой измененной секции | 1 173 480 блоков, масса 586 740 |
| История стыковочных операций с лимитом 16 | Ровно 16 записей, включая отказы `BUSY` |
| 10 000 новых запросов после заполнения истории | Все отклонены с `CAPACITY`; исходный ответ доступен для повторного UUID |

Счетчики `ShipStructure.WorkCounters` фиксируют обращения при обновлении сводок, принятые изменения агрегатов и элементы явных снимков. Движение вычисляется `OrbitState.at` без ссылки на `ShipStructure`; в модели нет поставщика блоков. Эти счетчики характеризуют операции этого API, а не инструментацию JVM и не стоимость будущего игрового адаптера. Unit-тест дополнительно проверяет неизменность агрегатов при движении, нетронутые секции и отдельную стоимость явного снимка.

Наблюдаемое время одного запуска: создание сводок **54,298 мс**, 100 000 поз **30,570 мс**, 64 запроса изменения **0,253 мс**. Время не является критерием успешности и не используется в assertions. Это одиночное наблюдение с JIT, выделениями памяти и без контроля фоновой нагрузки; повторяемость, распределения и предел производительности не установлены.

## Ограничения

Стенд не подтверждает поддержку миллиона реальных блоков в Minecraft. Он не измеряет первое сканирование корпуса, сохранение чанков, машины, меши, сеть, коллизии, GPU или MSPT. Первичная подготовка здесь проходит по сетке секций; движение не повторяет этот проход. Каждое принятое изменение пересчитывает агрегаты только одной секции, а `snapshot()` явно копирует все известные сводки и не должен вызываться на каждом тике движения.

История UUID ограничена без вытеснения старых ответов. После заполнения новые операции, включая переходы автомата, отклоняются: серверному адаптеру понадобится согласованный долговременный checkpoint и новая эпоха контроллера. Этот стенд не реализует такой checkpoint. Ограничение касается карты истории операций; оно не является общим лимитом памяти реестра портов или восстановленных соединений.

JUnit5-сценарии добавлены в `LargeSparseShipTest` и `DockingControllerTest`; их запуск через общую сборку остается у оркестратора. Отдельный стенд успешно компилирует чистые production-классы Java 21 и выполняет собственные проверки инвариантов.
