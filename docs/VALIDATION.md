## Alpha.4 — проверенное ядро и расширенный native probe

5 октября 2026 года. Core runner `tools/test.ps1` завершился успешно: **106 свежих JUnit, 19 suites, 0 failures/errors/skipped; 125 статических проверок; build/verifyCoreJar; 10 required core GameTest**. Ledger: `.tooling/test-runs/20261004T184653688Z-14552/status.json`. Артефакт: `build/libs/universe-0.1.0-alpha.4.jar`, SHA-256 `2594cc5a2a0f0ff7e23f4261cb5bc14892eb72d2f7ce7668dcf732a27d451544`.

В ядро вошли bounded/versioned PlanetSnapshotCodec и opt-in LivingGravityAdapter для выбранных vanilla мобов. Codec сохраняет определения и отклоняет поврежденные/неизвестные форматы; 5000 metadata roundtrip не является тестом 5000 Block или посещаемых планет. Девять gravity GameTest проверяют реальные воздушные траектории 32/16/0 м/с², повторное применение/release, актуальные foreign modifiers, NoGravity, conflict, активный off-thread отказ, два адаптера и разные entity instances. NoAI отключал travel; стенд оставляет AI включенным, убирая только goals. Игроки, lifecycle B, вода/полет/пассажиры и environment gameplay остаются открытыми.

LOD получил отдельные лимиты demand, memberships, subscribers/key и cache records сверх byte cap; identity acknowledgment рабочего task и обновление приоритета каждого активного подписчика. Восемь новых регрессий закрывают реальные memory/fanout и priority/forged-task дефекты. Независимый повторный source review одобрил этот срез; это ограничение метаданных, а не измерение времени рендера или больших кораблей.

После core runner отдельно выполнен native `runSableGameTestServer`: `.tooling/alpha4-native-final.log`, **все 10 required прошли** после усиления очистки и gameTime gates (3 прежних transfer controls, 3 A-калибровки, 2 velocity/invalid-capability, 2 B-компенсации). Native процесс завершился с кодом 0; ledger `.tooling/alpha4-native-final-status.json`. Источник проверен до commit, оба legs сохраняют полный chest NBT, V/ω и marker. Новый boundary capture на return измеряет уже изменившуюся скорость. Первый inventory failure устранен ожиданием обычной lifecycle-фазы до reuse slot; преждевременное отсутствие UUID не считается production storage barrier. Whole-dimension pause применена только в одноразовом стенде; клиенты, пассажиры, family, stable ShipId/native mapping и durable recovery этим не подтверждены.

B использует live scene config N=1/4, actual pre/post dt, массы 6/12, identity/90° и zero/nonzero target; `cross_substeps verified cases=8` и возврат original N=2 подтверждены финальным логом. gameTime, счетчики и сумма dt подтверждают четыре обычных игровых тика. Endpoint velocity согласуется, но импульс в начале подшага дает **реальный position bias**: при zero target за 0.2 s приблизительно +0.05194 блока (N=1) и +0.01294 (N=4). Формула bias и damping/solver bounds объявлены до проверки. Это полезная калибровка выбранного интегратора, не готовый физически неподвижный zero-g controller. Pending пара привязана weak key к сцене и потребляется после успешного сравнения; fresh JVM прогон подтвержден. Same-scene interactive rerun после незавершенной пары не имеет run epoch и отдельно не проверен.

В финальном отрицательном velocity-тесте реально отложенный callback после cleanup не создает тело и не регистрирует listener повторно. Снятие tickets, удаление всех owned объектов, unregister и восстановление pause выполняются независимыми попытками; незавершенное владение остается для retry. Независимое source review одобрило эти изменения; искусственные исключения каждого отдельного native cleanup API не инъецировались. Кандидаты lifecycle и клиентского стенда подготовлены вне main, но пока не скомпилированы и не запущены.

Длительности GameTest — лишь время выполнения небольших disposable тестов; MSPT, frame time, большие объекты, 5000 настоящих Block, restart/recovery и реальный клиент еще не измерены. Максимум DEVELOPMENT_LOOP не достигнут.
